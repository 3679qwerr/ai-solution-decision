# 执行、权限与失败恢复

本文件改编自 CZ / NativeHelix 的工作流、架构与 Harness 设计概念，已改写为产品决策场景；来源与修改见 [署名说明](../ATTRIBUTION.md)。

## 工具与任务契约

每个工具／阶段记录：输入 schema、输出 schema、数据来源、只读／有副作用、允许资源、执行身份、超时、尝试上限、幂等键、验收器与失败出口。生成文本不等于允许发送；模型建议不作为权限令牌。对检索证据先做 ACL 筛选再排序，不能只隐藏最终答案。

工具权限来自实际宿主，不来自此 Skill。区分当前明确授权、需进一步授权、禁止和未知。已授权范围内的可逆设计与本地计算直接做；新的付费、发送或生产写入在具体对象和影响可审阅后确认。批量操作给授权范围、有效期、预算和撤销方法，不逐条重复索取已覆盖的授权。

## 状态最小集

`created → running → validating → completed`；按实际需求增加 `waiting_approval / partial / failed / cancelled / quarantined`。审批拒绝走 cancelled；待审批超时保留草稿并结束本次执行，禁止无限等待后自动同意。

状态含 `run_id, task_id, version, attempt, owner, last_event, budget_used, checkpoint, artifact_refs`。对事件保存发生时间与接收时间；界面只投影真实状态，不从动画推断进度。stale 事件、重复事件和乱序事件应有明确处理。

## 失败分类与出口

| 失败 | 处理 | 禁止行为 |
|---|---|---|
| 暂时网络错误／429 | 有界退避，先检查总时限与预算 | 无限重试、绕过限额 |
| 检索无证据／权限不足 | 拒答、展示缺口或交人工 | 用模型记忆补业务事实、扩大权限 |
| 输出 schema 无效 | 标记失败；若允许重新生成，作为新 attempt 留痕 | 静默修补后声称原始结果有效 |
| 写请求超时、结果未知 | 查询幂等键／回执；状态 unresolved 并人工核对 | 盲目重复发送或扣费 |
| 部分任务成功 | 保留已验收工件，列出剩余项 | 把部分完成记作全部成功 |
| 冲突或污染输入 | 隔离工件、保留证据、仲裁 | 让生成者修改评分标准或自授权限 |
| 用户取消／预算到线 | 取消尚未开始工作；已发生副作用标注补偿能力 | 用重试重置预算或撤销不可逆事实 |

## 自治与多 Agent

仅当固定路径不足时增加规划循环；每个循环定义步数、时长、成本、无进展、连续错误与用户停止线。多 Agent 的每个子任务有独立输入、输出、资源范围、取消语义；合并者验证工件，检测版本与冲突。共享写必须隔离／锁定，审阅者不得因“看起来完成”而接受子 Agent 自报。

关键用户界面提供：目标和当前步骤、等待谁、累计成本、证据入口、错误及可行操作、暂停／取消／接管。接管后令旧执行令牌失效，防止后台继续写。

## 就绪判断

概念设计 → 本地手动 → 影子 → 限量真实运行，是需要不同证据的阶段。详细设计与离线检查不能证明真实运行可靠，更不能证明业务有效。评审按风险决定是否需要独立人员；作者自检必须标明。
