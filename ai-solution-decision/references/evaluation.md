# 产品评测方法

## 指标定义卡

| 类别 | 定义示例 | 采集与注意点 |
|---|---|---|
| 任务 | 通过预先冻结验收的任务数 / 所有有效分配任务数 | 超时与失败计入分母，取消原因分层；不要只报已完成样本 |
| 业务 | 每操作员工作周的有效采用次数；有对照的处理时间／转化差 | 区分使用者与付费者；不同场景选择一个主指标 |
| 成本 | 所有尝试与人工复核运营成本 / 验收成功数 | 分母为 0 时 unknown，不显示 0 元；TCO 另报 |
| 风险 | 未授权副作用数；证据不支持的重大主张数 / 审核主张数 | 严重越权单独否决，不能平均 |
| 运行 | 端到端 p95、恢复成功率、重复写入率 | 审批等待与纯计算延迟单列；注明窗口、样本数和未知 |

每项必须指定 owner、事件来源、窗口与阈值角色（真实基线／拟议目标／模拟）。目标由风险容忍、历史分布和单位经济推导，不是本 Skill 的通用常数。日志不能含原始敏感内容；使用引用 ID 与脱敏字段。

## 对照设计

现有人工／软件基线与最小 AI 候选先比较。相同样本、任务定义、资源预算，按任务类型、难度、语言与风险分层；避免训练或示例泄漏到盲测。指标与停止线预注册。离线评价不能直接推导收入；线上实验按用户或企业随机，处理污染、季节性与团队学习效应。样本量按预期差异和方差计算，缺这些信息时不给确定样本量结论。

方案扩复杂度使用消融：检索 vs RAG、固定流程 vs 单 Agent、单 vs 多 Agent；成本、延迟和风险与质量一起报。事实性、业务效果、安全性分开判定。任务成功率有区间，多次模型试验保留全部 attempt，不能挑最好一次。

## Skill 自身评测

实际工具在 [evals/PROTOCOL.md](../evals/PROTOCOL.md)：正／负触发、门槛回归、对抗、结构与人工质量评分分层。确定性检查证明代码不变量；导入的真实模型响应证明输出层行为；工具权限与真实副作用仍需轨迹证据和沙箱。未观测就写 unknown。
