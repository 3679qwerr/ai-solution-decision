# 技术选型：先门槛，再比较

## 三层组合

| 层 | 选项 | 决策问题 |
|---|---|---|
| 基础方法 | 人工／规则／传统算法／检索／LLM | 任务到底需要确定性、数值估计、信息定位还是语义生成？ |
| 知识增强 | 无／RAG | 回答是否依赖可追溯、私有或频繁更新的材料？ |
| 编排 | 直接调用／Workflow／单 Agent／多 Agent | 步骤是否固定？是否需要根据观察动态选择工具？任务能否独立并行且有净收益？ |

RAG 是检索加生成，Workflow 可包含 RAG；单 Agent 可以在有界 Workflow 中运行。不要通过单一“复杂度分”选定全部架构。传统模型可以配规则流程；产品可保留检索结果列表，不必生成自然语言回答。

## 候选适用边界

| 方案 | 优先适用 | 所需证据 | 主要代价／否决条件 |
|---|---|---|---|
| 现有流程／人工 | 低频、高不确定、尚无痛点基线 | 任务频率、人工时间与错误 | 可能扩展慢，但先验证需求可避免自动化浪费 |
| 规则 | 明确条件、可穷举策略、权限与阈值检查 | 输入字段、规则覆盖、例外集 | 例外不断增长时维护昂贵；不能承担开放语义理解 |
| 传统算法 | 数值预测、分类、优化、推荐排序 | 标签质量、离线切分、漂移与业务基线 | 数据不足不能承诺效果；LLM 不是数值任务默认解 |
| 检索 | 已有材料定位、条款和事实查找 | 文档可用性、权限、召回与新鲜度 | 无答案时应返回未找到；关键词/BM25 是向量检索对照 |
| 直接 LLM | 改写、归纳、语义抽取、开放生成 | 输出可验收样本、错误容忍、上下文范围 | 不保证事实；不可独自执行硬规则或权限判断 |
| RAG | 基于可追溯材料生成 | 检索必要性、证据覆盖、引用正确性、拒答集 | 召回、切块、ACL、注入和过期资料均需处理 |
| Workflow | 固定依赖、审批、重复任务、可恢复状态 | 步骤、状态、副作用、恢复契约 | 流程多不等于自治；状态机通常更容易验证 |
| 单 Agent | 工具路径事先无法列举、需观察后规划 | 固定流程失败实例、工具成功率、有界规划收益 | 预算、幂等、循环和权限失控；先限制工具与步数 |
| 多 Agent | 独立子目标／上下文隔离，合并可验证 | 与单 Agent 的匹配对照、通信与合并开销、冲突控制 | 角色多不是收益；共享写冲突、同源错误和成本放大 |

## 决策顺序与计算器输入

先澄清任务 → 排除不合硬约束的候选 → 建立最简单基线 → 验证增加复杂度的增量价值 → 记录决策与回退触发器。信息不足可以写“条件推荐”，不能伪装成已经验证。

`decision.py` 的 facts 是经过人工或模型分析后填写的显式事实，不直接读取附件文本：

- `task_known`：目标、输入输出及成功定义已足够形成候选。
- `structured_rules`：基础任务可由明确规则表达。
- `numeric_prediction`：主要目标是数值预测／排序，而非写一段解释。
- `knowledge_required`、`generation_required`：分别需要材料依据与开放生成。
- `fixed_steps`：多阶段依赖固定；`tool_execution`：需执行工具而非仅回答。
- `dynamic_planning`：下一步依赖观察结果，固定分支不足。
- `independent_subtasks`、`parallel_value_evidence`、`conflict_control_ready`：分别证明独立拆分、扣除沟通成本后的净收益、合并与取消可控。
- `runtime_feasible`：隐私、成本、延迟、依赖等硬约束综合判断；false 阻断，null 保留证据缺口。

所有事实可为 true／false／null，未给出等于未知。`candidate` 只表示这些声明足够形成候选，绝不表示审批或上线。脚本无法发现虚假声明、不可满足的自然语言需求或未建模的业务矛盾。

## 六维比较表

每个候选逐项填写以下字段，未知填写 unknown；不使用虚构 1–5 分取代测量。

| 维度 | 可观测定义 | 比较边界 |
|---|---|---|
| 质量 | 任务成功率、引用支持率、严重错误率 | 同任务集、同验收标准，含负例 |
| 成本 | 月费用、成功任务成本、12 月 TCO、必要时 36 月退出成本 | 模型、检索、工具、人工复核、维护、失败与重试 |
| 延迟 | 端到端 p50/p95、排队与等待审批单列 | 不能把各阶段 p95 简单相加当实测 |
| 稳定性 | 超时、重复副作用、恢复成功率 | 模型可用不代表业务完成 |
| 隐私 | 数据位置、最小读取、保留期限、删除、ACL | 硬约束不参与平均分 |
| 维护 | 规则／知识更新、人力、供应商切换、可观察性 | 原型成本不代表长期成本 |

若用户要求加权评分，先冻结权重和指标归一化方式，对未知做上下界敏感性分析；排序变化即标记决策不稳。若最便宜选项不满足质量下限，应拒绝或缩范围。
